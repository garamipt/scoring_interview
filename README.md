# Скоринг кредитных заявок по истории обращений клиента

Тестовое задание: предложить нейросетевое решение задачи, описать архитектуру,
план экспериментов и гипотезы. Подход реализован на TensorFlow/Keras,
гипотезы проверены на out-of-time валидации.

**Итог:** двухветочная нейросеть (энкодер текущей заявки + GRU по истории заявок)
даёт **test Gini 0,617** против 0,597 у градиентного бустинга на агрегатах;
бленд NN + GBDT — **0,626**.

## Задача и данные

- 794 201 заявка с бинарным таргетом (доля положительного класса 5,3%).
- Для каждой заявки — последовательность из 2–10 строк: текущая заявка (`NUM = 0`)
  и до 9 предыдущих заявок клиента по убыванию даты.
- Признаки: дата (`COL0`) и 158 анонимизированных бинарных колонок (`COL1–COL158`).
- Нужно предсказать таргет для текущей заявки.

**Валидация — out-of-time** по дате текущей заявки (2018 год):

| Сплит | Месяцы | Заявок | Доля таргета | Назначение |
|---|---|---|---|---|
| train | янв–сен | 564 718 | 5,27% | обучение |
| val | окт | 70 432 | 5,11% | early stopping, вес бленда |
| test | ноя–дек | 159 051 | 5,32% | итоговая оценка |

Метрика — Gini (= 2·ROC AUC − 1), дополнительно PR-AUC и Gini по месяцам теста.

## Ключевые выводы EDA

Подробно: [`reports/eda_report.md`](reports/eda_report.md).

1. **Признаки текущей заявки слабые** (IV ≤ 0,03 каждый). 66 колонок в текущей заявке
   константны, но 61 из них заполнены в прошлых заявках — вероятно, это поля исхода
   заявки (решение, выдача и т.п.), неизвестные на момент подачи.
2. **Основной сигнал — в истории**: признаки прошлых заявок до IV 0,23;
   «хотя бы в одной прошлой заявке» сильнее, чем «в последней прошлой заявке».
3. **Важна плотность обращений**: много заявок за короткий период повышает риск
   (Gini до 0,21 у счётчика заявок за 90 дней), при этом общее число заявок не важно.
4. **Утечек не найдено**: `IDX` — порядковый номер во времени (исключён из признаков),
   повторных клиентов между `IDX` нет, день недели и час не влияют на таргет.

## Архитектура

```
current app [92] ─ Dense(64) ──────────────────────────────────────┐
                                                                    ├─ concat ─ Dense(64) ─ Dropout ─ sigmoid
prev apps [9×153] ─ Dense(64) ─┬─ concat ─ GRU(64, masked) ────────┘
Δt [9×2] ──────────────────────┘
```

- **Две ветки с раздельными энкодерами**: у текущей заявки и у прошлых разный набор
  информативных колонок (поля исхода есть только в истории).
- **Энкодер заявки** (`Dense`) общий для всех прошлых заявок; к эмбеддингу добавляются
  `log1p(дней до текущей заявки)` и `log1p(интервал до следующей заявки)`.
- **GRU с маской** читает историю от свежих заявок к старым; пустые слоты пропускаются.
- Начальный bias = логит базовой доли таргета; BCE без весов классов (оптимизируем ранжирование).
- Adam, batch 1024, early stopping по val AUC, ReduceLROnPlateau. ~N тыс. параметров,
  обучение на CPU (MacBook Air M4).

Код: [`src/scoring/models.py`](src/scoring/models.py), [`scripts/train_nn.py`](scripts/train_nn.py).

### Проверка гипотез

Значимость — парный бутстрэп на тесте (200 ресемплов, 95% ДИ разницы Gini).

| # | Гипотеза | Результат | Δ Gini [95% ДИ] |
|---|---|---|---|
| H1 | История заявок добавляет сигнал к текущей заявке | ✅ подтверждена | NN: +0,310 [0,299; 0,321] |
| H2 | Последовательная NN лучше GBDT на агрегатах | ✅ подтверждена | +0,020 [0,015; 0,025] |
| H2' | Бленд NN + GBDT лучше каждой модели | ✅ подтверждена | +0,009 к NN [0,008; 0,011] |
| H3 | Явные временные признаки важны | ◐ частично | GBDT: +0,008 [0,005; 0,011]; NN: +0,003 [−0,001; 0,006] — незначимо |
| H4 | Достаточно последних заявок | ❌ опровергнута | вся история лучше последних 3: +0,034 [0,030; 0,038] |
| H6 | Модель стабильна во времени | ✅ для моделей с историей | Gini ноя ≈ дек; модели только на анкете проседают в декабре |

**Интерпретация.**
- Почти весь сигнал — в истории заявок; признаки текущей заявки работают только
  в комбинациях (GBDT/NN > LogReg).
- Выигрыш NN над GBDT достигается и без Δt: важна возможность видеть каждую
  прошлую заявку целиком и их порядок, а не только агрегаты.
- Порядок слотов уже кодирует «свежесть» заявки, поэтому явный Δt в NN почти не добавляет.
- Разрыв val → test (~0,02) у моделей с историей возникает между октябрём и ноябрём
  и дальше не растёт; вероятная причина — оптимизм валидации, на которой делались
  early stopping и выбор веса бленда (у LogReg, не использующей val, его нет).

## Ограничения

- Один сид на модель; бутстрэп учитывает шум тестовой выборки, но не шум обучения.
- Гиперпараметры не подбирались (ни для NN, ни для GBDT).
- Семантика колонок неизвестна. Допущение: исходы прошлых заявок известны
  на дату текущей заявки — проверить по данным нельзя; если это не так, сигнал истории завышен.
- EDA сокращён из-за сроков: структура one-hot, сходство текущей и прошлых заявок
  и дрейф признаков (PSI) не исследованы.

## Что проверить дальше

| Гипотеза / идея | Ожидание |
|---|---|
| H5: attention от текущей заявки к истории вместо GRU | модель найдёт прошлые заявки, похожие на текущую |
| Эмбеддинги по восстановленным категориальным полям (группы one-hot) | меньше параметров, лучше обобщение |
| Трансформер-энкодер по истории + временные эмбеддинги | паритет с GRU на коротких последовательностях, проверить |
| Self-supervised предобучение энкодера заявок (CoLES / masked modeling) | прирост, если есть неразмеченные истории |
| 3–5 сидов + усреднение | надёжная оценка H3, небольшой прирост от ансамбля |
| Подбор гиперпараметров (dim, dropout, lr) по val | +0,005–0,01 Gini |
| Веса классов / focal loss + калибровка | влияние на калибровку при сохранении Gini |
| Атрибуция (integrated gradients) по заявкам и колонкам | интерпретируемость для риск-менеджмента |
